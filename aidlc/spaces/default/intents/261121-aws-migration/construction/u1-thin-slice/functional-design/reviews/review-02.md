> R-01 Reviewer note: Release state now says only how far a Release came towards production. Where it runs comes from Deployments, which carry `notPutInPlace` and `inPlaceButFailing` outcomes per environment. W3 10a and 10b, W5 2a and 3a, and 6a and 6b in test cover the failure paths. Going back changes no Release state. The "exactly one running Release per environment" constraint is now derived from Deployments, so the diagram, the table and entities.md agree.

> R-02 Reviewer note: BR3.4 says waiting for approval does not hold later Releases back. W3 step 8 supersedes an earlier unapproved `verified` Release, and 9a and BR3.6 say a superseded Release can no longer be approved. `approved` is final, and only production Deployments are serialised. The two statements no longer conflict.

> R-03 Reviewer note: Access-password refusals are consistently outside the server and not Problems (BR2.1, BR2.4, BR1.5, open point 1). BR5.1 and the RequestLogEntry entity say the refusing layer records an entry with the operation "access refused". W6 excludes refusals from the error-rate count. AC9.3.1 and FR12.5 are now clear for refused requests.
