> R-01 Reviewer note: Stage 3 is now skipped when GitHub's record shows no earlier succeeded Deployment. Stage 4 updates `db-migrate` to this Release's package and names the exact published version. Bootstrap is folded into every runner start (try `migrator`, else create `app` and `migrator` from the master secret). The invoke has a raised client timeout and retries off, and repeats are harmless. The "first deployment" walk-through is consistent with the stage table.

> R-02 Reviewer note: A new "How each identity is confined" table gives a mechanism per resource kind: name prefix, `environment` tag conditions, and Route 53 record-name conditions. The RDS master secret is now Terraform-made and named `vd-<env>-db-master`. Several CloudFront, HTTP API, ACM and Route 53 conditions remain marked unverified, with a stated fallback (report the gap; one account per environment). This is acceptable as a design.

> R-03 Reviewer note: Custom error responses are removed. The `access-gate` function rewrites extensionless paths on the default behaviour only, and `/v1` is never rewritten.

> R-04 Reviewer note: `aws-migration` is made the default branch by the GitHub settings script, so `go-back` and `compare` can obtain the role trust. `compare` is not scheduled for production. The change needs the maintainer's agreement at the code plan, and the specification says so.

> R-05 Reviewer note: The topic policy is now listed, and the topic-first order is explained. It remains a departure from the mandated "budget alarm before any other AWS resource". The text calls it "a stated, minimal departure", but no maintainer approval is recorded.

> R-06 Reviewer note: The `alarms` variable is off in test in all three documents. The single dimension `environment` is used, and the count is eight of ten. The NFR11.6 row now agrees.

> R-07 Reviewer note: The pipeline document and monitoring-design now say who is told in each failure case (the `vd-alarms` topic for production failures after identity, GitHub's own email otherwise).

> R-08 Reviewer note: On a mismatch the server rereads the secret (at most once a minute) before refusing, so a rotation is covered.

> R-09 Reviewer note: The infrastructure-bearing NFRs (5.7 to 5.9, 10.2, 10.8 to 10.13, 11.8, 11.9, 14.2 to 14.4) now have rows. The NFR9.4 and NFR10.4 rows acknowledge the 8-second function limit.
