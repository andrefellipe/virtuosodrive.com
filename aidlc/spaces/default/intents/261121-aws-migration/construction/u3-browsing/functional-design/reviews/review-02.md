> R-01 Reviewer note: Both Folder and File now carry an optional, unique `sourceKey` (entities.md), shared across both kinds. Sample keys start "sample:" and U8 uses its own prefix. W6 finds items by that key, and Decision 5 and departure 4 record the addition to C9.

> R-02 Reviewer note: The contentless-file departure now has a closing plan in functional-spec.md ("How the contents stand-in is closed"), BR2.8 and BR2.10. U4 fills the sample files through the loader, and `contentId` becomes required on operations first. The store refuses an empty value only after the test environment has none. U7 and U8 never create contentless files. U4's tests do not rely on empty sample rows.

> R-03 Reviewer note: BR1.11 adds a visibility rule for `getVisibleFile`: one `notFound` answer whether the file is missing, deleted, or under a deleted folder. The sample set now calls the file inside the deleted folder hidden. `traceability.json` maps AC1.1.6 to BR1.11.

> R-04 Reviewer note: Space now toggles. Shift-Space and Shift with the arrows select a range. Escape then Space selects exactly one row. Keys that macOS keeps for itself are not relied on. The anchor is the focused row when none exists, and the table and BR4.3 agree for Shift-click and Ctrl-A.

> R-05 Reviewer note: BR2.11 and W7 make each change to one folder a single serialised step. The step checks or picks the name, takes the position, writes the item and raises the version. A lost race on `keepBoth` cannot happen inside the step. Only the store's duplicate-name refusal becomes `nameAlreadyUsed`, and any other store refusal becomes `serverError`.

> R-06 Reviewer note: BR2.4 to BR2.6 define the comparison once: NFC, Unicode white space trimmed, code points counted, default case folding, Cc and Cf rejected, and "." and ".." rejected. A name with nothing visible gives `nameEmpty`. The store holds the same rule.

> R-07 Reviewer note: BR2.7 now normalises and validates first, and gives the extension test, so "2019.1" and ".profile" have none. It still never says that folders have no extension. As written, a folder named "report.pdf" would become "report (1).pdf". A folder is not a file, so the rule should not apply there.

> R-08 Reviewer note: BR2.9 now includes a change to "changed by". entities.md (FolderView.version) and the U6 row in "What later Units find here" say the version must differ between callers who see the field and callers who do not.

> R-09 Reviewer note: BR4.7 defines a tap elsewhere on a row, the second tap on a file name, and the "Clear" control. BR4.6 and the W4 table cover the Delete key. A tick box is the only touch way to select several rows, and that matches what the mouse can do.

> R-10 Reviewer note: W3 now says a reload is not a refresh, and departure 3 records the 3-second timer as moving to U5. The text says AC2.1.6 is fully shown only when U5 and U6 exist. `traceability.json` still marks AC2.1.6 as plain "OK" with no note. This does not block the design. Add the note when the file is next touched.

> R-11 Reviewer note: BR3.1 gives "All" one address, the plain one, and rewrites the top folder's own identifier to it. BR2.12 states `notFound` for `checkName` and `lowestFreeName` on a folder that is unknown or deleted.
