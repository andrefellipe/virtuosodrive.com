### Checked and found sound

- C3 is honoured. `root`, 404 for missing, deleted and inside a deleted folder with one answer (BR1.4), 304 with no body, and no paging all appear. The order of steps in W1 returns `notFound` before "unchanged", so a version held for a folder that has since been hidden cannot hide the deletion.
- Items from C9 that are carried exactly: the record fields (apart from `contentId`), the visibility rule for folders, the name rules wording, and the version raised in the same operation as the change.
- One identifier set and one position sequence across folders and files is sound. It matches C3's single `itemId` per row and the contract's one set of names per folder, and it keeps restore returning to the old place (BR2.2).
- Deleted folder with visible items inside, and restore: the folder mark alone hides what is inside it. That matches C9's consequence, and the parent's version, not the folder's own, rises on delete and restore.
- Scope is sound. "Changed by", periodic re-asking, downloading, and change operations are left to U6, U5, U4 and U6. What `unit-of-work.md` assigns to U3 is present. No dependency on U2 or on a later Unit was found, other than the ones in the findings above.

### Summary

The functional design is thorough and follows C3 and C9 closely, and the contents departure is stated. It is not yet something U4, U6, U7 and U8 can build on without guessing. The frozen records lack a place for the source or sample key, the loader and U4's required contents do not fit together, file visibility under a deleted folder has no rule, writes to one folder have no serialisation, name comparison is under-defined, and keyboard-only selection on macOS fails AC2.1.5.
