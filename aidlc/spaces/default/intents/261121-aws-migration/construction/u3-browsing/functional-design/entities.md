# Entities: U3, browsing and selecting

The things U3 introduces. Folder and File are the first product records of
the system, and five later Units build on them: their shape is fixed here
and treated as unchangeable afterwards (contract C9). FolderView and Row are
answers, not stored. Selection lives only in the page.

```yaml
entities:
  - name: Folder
    description: >
      A place that holds files and other folders. Exactly one folder, the top
      folder named "All", has no parent.
    stored_in: database
    owner: Drive
    attributes:
      - name: folderId
        type: identifier
        required: true
        unique: true
        constraints: Generated by the server; opaque; never reused; unrelated to the name. Unique across folders and files together, so that an item is identified by one value.
      - name: name
        type: text
        required: true
        min: 1
        max: 255
        constraints: Follows the name rules (rules BR2.4 to BR2.6) and is stored in the normalised form of BR2.4. Length is counted in Unicode code points of that form. The top folder's name is "All".
      - name: parentFolderId
        type: identifier
        required: false
        references: Folder.folderId
        constraints: Empty only for the top folder. A folder is never its own ancestor.
      - name: position
        type: whole number
        required: false
        constraints: The folder's place in its parent's list, lowest first. Given once when the folder is created and never changed. Unique among all items of the same parent, deleted ones included. Empty only for the top folder.
      - name: version
        type: whole number
        required: true
        default: 1
        constraints: Rises by one, in the same operation, whenever the list of this folder's visible items changes. Never falls.
      - name: createdAt
        type: timestamp (UTC)
        required: true
      - name: lastChangedByAccountId
        type: identifier of an account
        required: false
        constraints: Always empty in U3. Filled by U6 and U7.
      - name: lastChangedAt
        type: timestamp (UTC)
        required: false
        constraints: Always empty in U3.
      - name: deletedAt
        type: timestamp (UTC)
        required: false
        constraints: Set only on an item a person deleted directly, never on what is inside it. Nothing in U3 sets it except prepared sample content.
      - name: deletedByAccountId
        type: identifier of an account
        required: false
        constraints: Always empty in U3.
      - name: broughtOver
        type: boolean
        required: true
        default: false
        constraints: True only for items the migration (U8) creates.
      - name: sourceKey
        type: text
        required: false
        unique: true
        constraints: >
          Where an item made by a loader came from, so that running the
          loader again finds the item it already made. Empty for every item
          a person creates. Sample content uses keys starting "sample:"; the
          migration (U8) uses the old system's keys under its own prefix.
          Unique across folders and files together. Never shown, never
          returned by any route, never changed after creation.
    constraints:
      - Exactly one folder has no parent; it cannot be deleted, renamed or moved, in this Unit or any later one.
      - Every other folder has a parent that exists.
    relationships:
      - target: Folder
        kind: parent
        cardinality: many folders to one parent folder
      - target: File
        kind: holds
        cardinality: one folder to many files

  - name: File
    description: >
      One file's listing: its name, size and type, and where its contents are
      kept. The contents themselves are not part of this record.
    stored_in: database
    owner: Drive
    attributes:
      - name: fileId
        type: identifier
        required: true
        unique: true
        constraints: As Folder.folderId, and drawn from the same set of values.
      - name: name
        type: text
        required: true
        min: 1
        max: 255
        constraints: Follows the name rules.
      - name: folderId
        type: identifier
        required: true
        references: Folder.folderId
      - name: position
        type: whole number
        required: true
        constraints: As Folder.position; folders and files of one parent share one sequence.
      - name: size
        type: whole number of bytes
        required: true
        min: 0
      - name: contentType
        type: text
        required: false
        constraints: The type the file was stored with, for example "application/pdf". Chooses the icon and nothing else in this Unit.
      - name: contentId
        type: identifier of stored contents (contract C10)
        required: false
        constraints: >
          Empty for every file in U3, because stored contents arrive with U4
          (answer Q2). A file without contents is listed but cannot be
          downloaded or opened. Closing this is U4's work, in three steps set
          out in functional-spec.md ("How the contents stand-in is closed"):
          U4 stores contents for each sample file and its loader fills this
          attribute on the sample rows that lack it; from U4 on, every
          operation that creates a file requires a contentId; and once no
          file without contents exists in either environment, U4 has the
          store refuse an empty value. Once set, it is never emptied.
      - name: createdAt
        type: timestamp (UTC)
        required: true
      - name: lastChangedByAccountId
        type: identifier of an account
        required: false
        constraints: Always empty in U3.
      - name: lastChangedAt
        type: timestamp (UTC)
        required: false
        constraints: Always empty in U3.
      - name: deletedAt
        type: timestamp (UTC)
        required: false
      - name: deletedByAccountId
        type: identifier of an account
        required: false
        constraints: Always empty in U3.
      - name: deletedReason
        type: enumeration
        required: false
        allowed_values:
          - deleted
          - replaced
        constraints: Set exactly when deletedAt is set.
      - name: broughtOver
        type: boolean
        required: true
        default: false
      - name: sourceKey
        type: text
        required: false
        unique: true
        constraints: As Folder.sourceKey, and unique across the same set.
    constraints:
      - A file always belongs to exactly one folder that exists.
    relationships:
      - target: Folder
        kind: is in
        cardinality: many files to one folder

  - name: FolderView
    description: >
      The answer to "show me this folder": the folder, the path to it from
      "All", and its visible items in order. Contract C3.
    stored_in: nowhere; computed for each request
    owner: Drive
    attributes:
      - name: folderId
        type: identifier
        required: true
      - name: name
        type: text
        required: true
      - name: path
        type: ordered list of (folderId, name)
        required: true
        constraints: From "All" to this folder, both included. For "All" it holds one step.
      - name: items
        type: ordered list of Row
        required: true
        constraints: Visible items only, lowest position first. May be empty.
      - name: version
        type: text
        required: true
        constraints: Travels beside the answer, not inside it (contract C3's ETag). Two answers for one folder with the same version list the same items in the same order. When U6 adds "changed by" for signed-in callers, the version sent must also differ between a caller who is shown it and one who is not; U3 has only one kind of caller.
    constraints: []
    relationships:
      - target: Row
        kind: lists
        cardinality: one view to many rows

  - name: Row
    description: One visible item as the list shows it. Contract C3 calls it Item.
    stored_in: nowhere; computed
    owner: Drive
    attributes:
      - name: itemId
        type: identifier
        required: true
        constraints: The folderId or fileId.
      - name: kind
        type: enumeration
        required: true
        allowed_values:
          - folder
          - file
      - name: name
        type: text
        required: true
      - name: size
        type: whole number of bytes
        required: false
        constraints: Present for a file, absent for a folder.
      - name: contentType
        type: text
        required: false
        constraints: Present for a file when one was recorded.
    constraints:
      - Carries no "changed by" in U3 (answer Q1). U6 adds it, as contract C3 already allows; the page ignores what it does not know.
    relationships: []

  - name: Selection
    description: >
      The rows of the open folder that the visitor has picked for an action.
    stored_in: the page only; never sent to the server in this Unit
    owner: WebClient
    attributes:
      - name: itemIds
        type: set of identifiers
        required: true
        constraints: Each belongs to a row of the open folder. May be empty.
      - name: anchorItemId
        type: identifier
        required: false
        constraints: The row last chosen on its own or by toggling; the fixed end of a range. Empty when nothing has been chosen in this folder.
      - name: focusedItemId
        type: identifier
        required: false
        constraints: The row the keyboard is on. Independent of what is selected.
    constraints:
      - Belongs to one open folder; opening another folder starts an empty selection.
    relationships:
      - target: Row
        kind: picks
        cardinality: one selection to many rows
```

## Summary

| Entity | Kept where | What it is for |
|--------|------------|----------------|
| Folder | Database | Holds items; one top folder, "All" |
| File | Database | A file's listing; contents are separate and arrive with U4 |
| FolderView | Computed | What one request for a folder returns |
| Row | Computed | One visible item in a FolderView |
| Selection | The page | Which rows an action would apply to |

## Decisions recorded here

1. **One set of identifiers and one sequence of positions for folders and files.** Contract C9 left open whether folders and files are one table or two. The design needs three things that hold across both kinds: one identifier per row of the list (contract C3's `itemId`), one order per folder, and one set of names per folder. They are therefore specified as two kinds of one "item", and the recommendation to the code step is one stored collection with a kind. The records still read as contract C9 describes them; no consumer sees the difference.
2. **Positions are never renumbered.** A new item takes the next number after the highest ever used in its folder. Deleted items keep theirs, so a restored item returns to its old place and "oldest first" (FR1.4) never shifts.
3. **`contentId` may be empty until U4** (answer Q2). It is a temporary departure from contract C9 as written, and U4 closes it in the three steps named on the attribute.
4. **`lastChangedBy`, `deletedBy` and `broughtOver` exist from the start** but nothing in U3 fills them, so that U6, U7 and U8 add behaviour without changing the shape.
5. **`sourceKey` is added to both records.** Contract C9's records do not list it, yet its import operations promise that repeating a `sourceKey` returns the item already made, and the sample loader needs the same promise. Without a stored key neither can be kept, and the shape cannot change after this Unit. This is an addition to contract C9's records, made here because U3 owns them.
6. **Additions to contract C9, in one place:** `sourceKey` (above); the name rules made exact (rules BR2.4 to BR2.7); and the rule that every change to one folder's list is one step at a time (rule BR2.11). None removes or renames anything a consumer was promised.
