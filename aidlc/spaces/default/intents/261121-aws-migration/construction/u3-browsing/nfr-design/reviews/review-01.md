### What I checked and found sound

- **ServerFailures**: `outcome >= 500` in `measurements.ts` is as O21 claims, so 404 and 304 are not failures.
- **P20 statement counts**: one statement without a version, one or two with a version. The design is internally consistent, and a single statement does give one snapshot (R20), apart from the visibility gap noted above.
- **S27 order**: walk (visibility) first, then compare versions, then "everything". Correct for the "unchanged" path.
- **Deadline and connection**: a transaction left open by a timeout is rolled back, because `discard()` ends the kept connection. The design's claim holds, provided the new method follows the same rule.
- **Edge routing**: `/v1/*` goes to the server with caching disabled; the server's catch-all route takes the new path; the gate's rewrite of paths with no extension gives a folder address the entry document. The page address must not contain a dot or begin with `/v1`.
- **NFR10.25 coverage**: every refusal the requirement lists can be held by a unique or check constraint or a reference, with no trigger.
- **Sample loader order and idempotence (R24, R25)**: sound; `source_key` makes it repeatable.

### What I could not check

- Whether the access-gate source rewrites the planned page address (I read only its description in U1's specification and the module comment).
- Whether CloudFront forwards `If-None-Match` or `Accept-Encoding` by default with caching disabled. I relied on the request policy as written; an end-to-end run is the proof.
- The `pg_c_utf8` and `casefold` behaviour, and the effect of the generated column, which I took from the design's own container check.
- `db-migrate`'s user-creation file and grants (not in the scope I could read).

### Summary

The mechanisms are mostly sound at the database level, but the design assumes U1's request steps, call function and edge already do things they cannot: path values, 404 for a malformed identifier, request and response headers, 304, compressed bodies and extra log fields. It also checks the answer's size on a quantity the platform does not limit. It makes a functional and contract change without asking, and narrows NFR3.24 without saying so. These need to be fixed or recorded before the next stages build on them.
